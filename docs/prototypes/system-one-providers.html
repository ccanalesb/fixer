PROTOTYPE — System One endpoints as providers

Three variants of the same idea: a System One endpoint is a provider (protocol: "system_one" in providers.json), and a culling stage chooses This app or one of those providers. Switch variants and scenarios in the bar at the bottom. Click things: add a provider, park it, remove it, pick it in a stage.

Assumed in every variant, not decided yet: a System One stage still picks its model from the endpoint's GET /v1/models list, as Culling models does today (the "models are typed in by hand" decision was about OpenAI-compatible providers).

1 · Processing → Providers

2 · Settings → Culling models

3 · Providers → Default models (description fallback list)

Same in every variant: only OpenAI-compatible providers can be in the description cascade; System One providers never appear here.
